# Product

## Register

product

## Users

Players who want to run legally owned Windows games and installers directly on Android phones and handheld consoles. Phone and controller-first use are equally important. Users may navigate with touch, Xbox-compatible controllers, or DualSense/PS5-compatible controllers and should be able to complete every primary workflow without switching input methods.

## Product Purpose

Provide one dependable Android library for installing, configuring, and launching local Windows games while retaining GameNative's Steam connection and existing container workflow. Selecting an installer should create a game container and continue through the same configuration, compatibility, controls, and launch systems used by GameNative. Success means that importing, installing, finding, configuring, and launching a game feels coherent rather than like operating a collection of emulation tools.

## Brand Personality

Convenient, adaptable, and technically dependable. The interface should inherit the clarity and controller fluency associated with Steam Deck and Xbox One without copying either product. It should feel calm and purposeful rather than aggressively "gamer" styled.

## Anti-references

Avoid GameNative's current visual clutter, acidic neon color palettes, excessive decoration, glassmorphism, oversized rounded cards, gratuitous animation, and generic AI-generated dashboard styling. Avoid interfaces that expose implementation details before users need them or require touch to escape controller-navigation dead ends.

## Design Principles

1. One task, one clear next action: installation and launch flows disclose technical choices progressively.
2. Input parity by construction: touch, Xbox-compatible controllers, and DualSense-compatible controllers are first-class and can complete the same workflows.
3. Familiar console navigation: focus, selection, back behavior, and button hints remain predictable across every screen.
4. Customization without fragility: themes may transform the product extensively but must preserve semantic roles, operability, and recovery to a safe built-in theme.
5. Compatibility is explained, not hidden: failures identify the affected layer and offer actionable recovery without overwhelming routine use.

## Accessibility & Inclusion

Target WCAG 2.2 AA where applicable to an Android game launcher. Support system text scaling, high-contrast themes, reduced motion, non-color-only state communication, screen-reader semantics, minimum touch targets, and complete non-touch navigation. User themes must be validated for minimum contrast and required semantic tokens; unsafe themes should be warned about and recoverable without blocking access to settings.
